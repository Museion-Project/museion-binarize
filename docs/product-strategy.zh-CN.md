# Museion 产品、开源与可持续运营方案

**状态：** 产品方向决策记录  
**日期：** 2026-08-25  
**适用范围：** Museion 整体产品组合，以及本仓库从 M PDF 处理器向下一代 PDF 工具演进的边界

> 本文描述产品方向，不代表当前版本已经实现文中所有功能。当前可用能力与限制仍以
> [README.zh-CN.md](../README.zh-CN.md) 和 [limitations.md](limitations.md) 为准。

## 1. 一句话定位

Museion 是面向古典学与数字人文的开放研究基础设施：研究方法、数据格式和本地处理
工具保持免费开源；移动端产品体验、托管计算、团队协作、部署维护与机构服务收费。

这不是“免费版缺功能、付费版解锁学术能力”的传统 freemium 模式。Museion 不把学者
对研究材料的本地自主权和数据出口锁在付费墙后，而是对下列真实成本收费：

- 原生移动端扫描和完整工作流的产品化；
- App Store 等便利分发、持续适配和维护；
- 云端模型、GPU、存储和任务队列；
- 多用户权限、审计、协作校订和系统集成；
- 机构部署、培训、支持与服务保障。

## 2. 产品组合

### 2.1 Museion Reader：`museion.me`

集成古代文本、译文、apparatus、术语系统、语义单元和 AI 辅助阅读的古代文本工作站。
它是 Museion 的学术主界面，也是其他工具产出机器可读材料后的主要消费端。

### 2.2 Museion Chinese LSJ

中文古希腊语词典基础设施。产品应保留机器翻译来源、版本、置信度和人工修订记录，
将其表述为“可追溯、可修订、持续演化的中文 LSJ”，而非不可验证的成品翻译。

### 2.3 M PDF 处理器

本仓库下一阶段产品的建议名称：

- 应用展示名：**M PDF 处理器**；
- 中文副标题：**扫描、古希腊文 OCR 与书签**；
- 下一代仓库名候选：`mpdf`；
- `mpdf-core` 保留为核心处理模块名，而不再承担完整产品名称。

名称优先覆盖用户真实搜索意图：PDF、OCR、扫描、书签。`mpdf` 对开发者精确，但不是
大多数用户会主动搜索的词。

目标能力包括：

1. M PDF 处理器核心：自适应二值化、真正 1-bit PDF 与高效压缩；
2. OCR：普通文字和多音调古希腊文，保留文字坐标与置信度；
3. Bookmark：从目录页、标题层级和 OCR 证据生成可核验书签；
4. Scan：手机拍摄、裁剪、透视矫正、双页分割、书页展平和光照校正；
5. Document Package：机器可读性强、格式开放的中间产品；
6. Export：可搜索 PDF、结构化文本和数字人文交换格式。

## 3. Museion Document Package 是技术中轴

机器可读中间层不是 PDF 产品的附加功能，而是连接整个 Museion 产品组合的核心协议。
建议暂称 **Museion Document Package（MDP）**，最终名称和版本号应在实现前单独确定。

```text
扫描照片 / 现有 PDF
        │
        ▼
不可变原始页面 + 来源记录
        │
        ▼
几何矫正 / 展平 / 光照校正
        │
        ▼
高质量彩色或灰度母版
   ┌────┼──────────┐
   │    │          │
   ▼    ▼          ▼
OCR候选 真1-bit PDF 页面缩略图
   │
   ▼
文字、坐标、版面、页码、目录、置信度
        │
        ▼
Museion Document Package
   ┌────┼──────────┐
   ▼    ▼          ▼
专业PDF Museion Reader 其他数字人文工具
```

### 3.1 最低数据要求

每个文档包至少应包含：

- 原始输入和内容摘要，或对不可嵌入原件的稳定引用；
- 每页原图、处理后母版和二值化派生物之间的关系；
- 页序、印刷页码、图像尺寸、分辨率、旋转与裁剪坐标；
- OCR 文字、行/词/字坐标、语言、引擎、模型版本和置信度；
- 栏、段落、标题、脚注、apparatus、图表等版面区域；
- 目录层级、PDF 书签及其证据页；
- 每一步处理参数、软件版本、时间和来源记录；
- 明确区分机器推断、人工确认和人工修订。

### 3.2 开放原则

- MDP 规范开放并版本化；
- 优先复用 PDF、JSON、ALTO、PAGE XML、hOCR 等已有标准，不制造封闭数据孤岛；
- 用户始终可以导出完整结构化数据；
- Museion 的优势来自产出质量、古典学适配和工具间互操作，而不是格式锁定。

## 4. 正确的 PDF/OCR 处理链

不得把流水线简单实现为“先二值化，再 OCR”。激进二值化可能抹掉希腊文重音、气息、
下标 iota、脚注上标和校勘符号。

建议保留不可变原图，并从校正后的母版并行生成多种 OCR 候选：原始/灰度增强、保守
二值和自适应二值。OCR 层逐页比较置信度和结构一致性，再选择或融合结果。二值化主要
服务于阅读清晰度、打印和紧凑 PDF；它不应成为 OCR 唯一输入。

OCR 引擎应保持可替换：

- 历史文献和古希腊文主引擎候选：Kraken；
- 本地快速回退：Tesseract `grc` 等可复现引擎；
- Gemini Flash 等视觉模型：疑难页理解、版面/目录推断和 OCR 校订；
- 不把任何单一商业模型名称写死为 Museion 的产品能力。

AI 书签必须由 OCR 坐标、目录页和标题层级提供证据；不得在无证据时虚构章节或页码。

## 5. 手机扫描策略

### 5.1 第一阶段：先吃掉工作流

```text
夸克扫描王完成扫描
        ▼
分享到 / Open in Museion
        ▼
二值化 + 古希腊文 OCR + AI 书签
        ▼
专业可搜索 PDF + MDP
```

这一步让用户继续使用已经信任的拍摄工具，同时验证 Museion 后半段工作流的付费价值。

### 5.2 第二阶段：内置系统文档相机

- iOS 以 VisionKit 文档相机作为稳定起点；
- Android 以 ML Kit 文档扫描器作为设备端起点；
- M PDF 处理器增加面向古典学书籍的保守处理：双页分割、书脊弯曲、泛黄纸张、阴影、
  小号 apparatus 和多音调希腊文保护。

### 5.3 夸克 API 的位置

夸克已经开放文件扫描、裁剪矫正、去阴影、去底色和画质增强 API，可作为短期评测对象
和可选“云端抢救”模式，但不作为永久唯一依赖：

- API 按调用次数收费，会形成每页可变成本；
- 文件需要上传云端，必须处理用户同意、数据协议和地区合规；
- API 密钥只能保存在 Museion 后端，不能写入手机 App；
- 官方“20+ 语言”说明没有确认古希腊文，Museion 仍掌握古希腊文 OCR；
- API 与消费端 App 的输出质量是否一致必须实测；
- 商业模型增强不得无条件替换原件，也不得以生成式细节作为学术原文。

长期路线是逐项把裁剪、透视、光照、双页分割和书页展平收回 M PDF 处理器本地引擎。

## 6. 开源与收费边界

| 层级 | 免费开源 | 个人付费应用 | 机构订阅 |
|---|---|---|---|
| 核心算法 | 本地二值化、基础 OCR、结构提取 | 原生封装使用 | 服务器封装使用 |
| 数据格式 | MDP 开放规范、完整导出 | 完整导入导出 | API 和系统集成 |
| 桌面端 | 功能完整的 CLI 与桌面 GUI | 可有商店便利分发 | 连接机构服务 |
| 手机端 | 可开放共享核心库 | 扫描、分享入口、后台任务、完整移动体验 | 机构账号和受管部署 |
| 计算资源 | 用户自己的设备 | 本地计算；云增强另计 | GPU、云模型、队列和配额 |
| 批处理 | 用户可在本地脚本化 | 设备内有限任务管理 | 集中式大规模并发与恢复 |
| 协作管理 | 无或社区工具 | 个人文档 | 多用户、权限、审计、共享校订 |
| 支持 | 社区支持 | 产品更新 | SLA、部署、培训和技术支持 |

“Batch”不能定义为简单的多文件循环：开源 CLI 天然可以被脚本循环调用。机构 batch 的
价值是可恢复任务队列、多机并发、共享算力、权限、审计、费用治理和团队校订。

### 6.1 个人端收费

- 手机 App 可对原生扫描、完整移动工作流、稳定更新和商店分发收费；
- 本地功能适合买断；
- 有持续单页成本的夸克/Gemini 云功能不能承诺一次买断后无限使用；
- 若未来引入订阅，应对应持续发生的云计算或同步服务，而不是人为锁住本地学术能力。

### 6.2 机构收费

- 托管服务器或私有部署；
- 大规模批处理、GPU 和多引擎调度；
- SSO、用户权限、日志、审计和共享校订；
- API、存储策略、备份、迁移和 SLA；
- 模型成本管理与可配置数据保留策略；
- 培训、集成和长期技术支持。

### 6.3 GitHub Sponsors

Sponsors 用于支持开放研究工具，不承担主要商业模型。它可以积累社区认可，但无法替代
可预测的 App 销售和机构合同，也不替代收款者所在地的税务义务。

## 7. 经营主体建议（德国假设）

Apple Developer 和 GitHub Sponsors 是分发/收款渠道，不是税务或法律主体。建议分阶段：

1. 仅开发、开源和无收入验证时，可以保持个人项目；
2. 开始收款时，以 `Einzelunternehmen / Gewerbe` 或税务机关确认的适当身份登记并记账；
3. 付费 App 正式上线前，决定是否接受个人法定姓名作为 App Store 卖家；
4. 若要以 Museion 品牌作为卖家、签机构合同、处理云端文档或建立团队，优先考虑
   `Museion UG (haftungsbeschränkt)`；
5. GmbH 在已有稳定收入、人员或投资需求之前通常过重。

这是产品规划，不是个别税务或法律意见；正式收款前应由德国 Steuerberater 核对经营
分类、增值税、Apple/GitHub 收入和机构开票方式。

## 8. 评测与发布路线

### Release A：当前 M PDF 处理器基础工具

- 维持当前名称和应用标识，避免在候选版阶段破坏升级路径；
- 发布本地二值化、预览、估算、转换和拖入 PDF；
- 不声称包含 OCR、AI、书签或扫描矫正；
- 继续免费开源和提供 GitHub 二进制包。

### Release B：PDF 结构化桌面原型

- 引入 OCR 引擎接口、古希腊文基准数据和坐标化输出；
- 定义 MDP 0.x 草案；
- 从 OCR 证据生成可核验目录书签；
- 产品/仓库重命名必须另做迁移方案，保留包标识和用户升级路径。

### Release C：手机端最小产品

- 接收夸克、文件 App、照片库和系统分享的 PDF/图片；
- 本地二值化、古希腊文 OCR、书签和可搜索 PDF；
- 先验证“从扫描到专业 PDF”的完整付费任务，再投入自研相机。

### Release D：M PDF 处理器内置扫描

- 系统文档相机起步；
- 逐步加入双页分割、书页展平、光照校正和学术保真模式；
- 夸克云增强仅在合同、成本、隐私和效果评测通过后作为可选后备。

### Institution

- 在单机格式和质量稳定后建设服务器任务队列；
- 多引擎 OCR、AI 校订、多人校勘、API 和受管存储；
- 不为机构版制造与开源格式不兼容的数据锁定。

## 9. 质量基准

用真实古典学材料建立不少于 200 页的初始评测集，覆盖：

- 清晰现代版、历史版、泛黄和低对比度页面；
- 多音调古希腊文、拉丁文及多语言混排；
- 双栏、脚注、apparatus、页眉页脚和印刷页码；
- 双页拍摄、书脊弯曲、阴影、倾斜和模糊；
- 小号重音、气息、下标 iota、校勘符号和上标。

比较原始照片、系统扫描、夸克 App 输出、夸克 API 输出和 M PDF 处理器本地处理。指标包括：

- 基础字母字符错误率；
- 附加符号错误率；
- 校勘符号和脚注保留率；
- 行弯曲/透视误差；
- 目录与书签页码准确率；
- 人工修订时间、延迟、峰值内存、文件大小和每页成本。

视觉上“更白、更锐”不能代替字符保真度。任何超分辨率或生成式增强都必须与原件并存、
保留来源记录，并且不能成为学术 OCR 的无标记事实来源。

## 10. 需要长期坚持的边界

1. 开放方法、格式和本地自主权；收费便利、算力、协作和服务。
2. 不以闭源格式或不可导出的用户数据制造锁定。
3. 不将生成式恢复伪装成原始文献内容。
4. 不因商业模型而削弱开源桌面版已经承诺的完整本地功能。
5. 不把 Museion 的产品能力绑定在夸克、Gemini 或任何单一供应商上。
6. 研究工具、产品收入和用户反馈形成同一循环：研究发现需求，开源工具建立信誉，
   移动端与机构服务反哺研究。
