# 显式处理动作与打开时页码重建

意图基线：`intent.md` §8.38 PG1–PG4。用户来源为本任务 2026-09-10 十项实操反馈及“预设移入高级设置”澄清。此次授权为本地实现、验证和 commit，不含 push 或发布。

## 行为与证据

- PG1 aligned：范围与分辨率左侧对齐，无范围分割线；预设位于折叠高级设置。黑白栏右侧“开始”执行真实二值化并缓存结果，目录栏右侧“生成”。保存复用与源 SHA、参数、范围绑定的结果；修改后必须再次开始。真实窗口截图 `native-ui.png`，Menn 真实 IPC 开始→生成→保存见 `native-ui.jsonl`。
- PG2 aligned（本地已测路径）：打开或拖入后启动独立于 PDFium 预览队列的文档分析。原生文字读取可见页边页码；无文字层时 Apple Vision fast 仅识别上下 14% 页边，分三块读取细小数字。先随机分层抽样，必要时补查相邻页和前言；上限 18 个物理页不是最少锚点要求，每段仅要求至少两个独立一致页。识别目录页页眉并排除其页码，避免自证。最终扫描样本 16 个抽样页、7 个可靠页码，独立调用 1.75 秒完成两套规则；真实桌面从打开到状态就绪 4.18 秒。首次 Swift 编译、硬件和书本差异仍影响耗时，不承诺固定 20 秒。
- PG3 aligned（已测路径）：缓存源绑定页码模型，生成目录时复用并再次排除目录页证据；保留精确观测、分段推断及多候选。支持 Roman/Arabic、编号重启、连续左右页的双页扫描；非匀速重排 PDF 优先使用真实可见原页码。底栏显示文字层及重建状态，换文档清除旧结果。全书规则不是对每页均已目检的声明。
- PG4 aligned（本地开发范围）：原生 Horn 18 条、Menn 11 条目录的物理目标全部与既有来源核对一致；Brisson 双页扫描的 printed 64 修正为物理 PDF 第 32 页，已有目录 OCR 漏读的一项仍保留待填。Menn 保存输出 202 页、11 个有效书签，只有第 16 页二值化，其余 201 页文本及缩小渲染逐页相等。1466 个原输入、历史证据和保护文件 SHA 全部保持不变。未消费 Gold/holdout，未调用云服务。

## 真实桌面扫描路径的限度

`native-ui-final.jsonl` 和 `native-targets-final.json`：原生 Horn 打开后约 5.73 秒就绪，18/18 目标关联；由同书生成的无文字层 PDF 打开后约 4.18 秒就绪，目录 18 条中 17 条目标正确关联，包括前言罗马页码。另 1 条 Introduction 的 printed page 被原目录 OCR 漏读，保留待填，未凭标题猜成页 1。扫描目录标题仍有 Apple Vision fast 识别错误，本轮没有变更整页目录 OCR 引擎，也不声称扫描目录识别无误。

`vision-analysis`/`vision-analysis-v2` 等早期证据保留：第一轮缺罗马页码；一次沙箱内 Vision 返回 CVPixelBuffer 错误；后续发现目录页锚点被排除导致前言映射丢失。最终以非目录页 viii/ix 独立确认。早期失败不记为通过。

少量抽样不能保证发现所有未抽中的短编号段、插页或漏印页码。规则冲突和重复编号无法唯一消歧时保留候选；合成重启/歧义测试不等于所有真实书型均已验证。加密 PDF/不可用本地运行时明确报告不可用。开关文件对话框由调试 fixture 提供，PDF 打开、分析、生成与保存均为真实 IPC；普通 release 不含测试入口。
